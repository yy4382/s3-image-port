作为一个管理 S3 上图片的工具，S3 Image Port 需要您提供 S3 储存桶的信息来访问、上传图片。

## 配置 S3（或其他兼容 S3 协议的服务）

如果您还没有一个 S3 储存桶，请根据下面的指南创建一个。简单来讲，这需要 3 步：

1. 在对应平台上创建 S3 兼容的储存桶。
2. 获取访问储存桶所需的端点、密钥等信息。
3. 设置储存桶的访问权限和 CORS。

以上 3 点都是使用 S3 Image Port 必不可少的步骤。

<Callout type="warning">
浏览器跨域访问存储桶需要 CORS 允许当前站点。网络异常也可能来自端点、DNS、TLS、代理或浏览器拦截，不能仅凭“连不上”确定原因。

关于如何配置 CORS，请继续阅读。

</Callout>

### 通用要求

S3 Image Port 需要以下信息/权限以正常工作：

1. `Endpoint`, `Region`, `Access Key ID`, `Secret Access Key` 等连接用的信息，
2. 一个直接用来访问图片的链接前缀，我们称之为 `Public URL`，
3. 正确的 CORS 配置。

第一点不多赘述，可以自行查询如何获取。

#### Public URL

在目前版本 (1.6.0) 中，储存桶中的图片必须可以通过一个链接直接访问。

例如，一张图片在储存桶中的路径是 `i/2024/05/29/name.jpg`，而你可以通过 `https://i.yfi.moe/i/2024/05/29/name.jpg` 这个链接直接（不需要验证地）访问到它，那么 `https://i.yfi.moe/` 就是你需要填写的 Public URL.

如果你直接使用了某些 S3 兼容服务的“公开储存桶”功能，也是同理。例如，对于 Cloudflare R2，它应该形如 `https://pub-<一堆字符>.r2.dev`。对于腾讯云 COS，应该形如 `https://<BucketName-APPID>.cos.<Region>.myqcloud.com`

#### CORS 配置

<Callout title="什么是 CORS？">
**跨源资源共享**（[CORS](https://developer.mozilla.org/zh-CN/docs/Glossary/CORS)，或通俗地译为跨域资源共享）是一种基于 [HTTP](https://developer.mozilla.org/zh-CN/docs/Glossary/HTTP) 头的机制，该机制通过允许服务器标示除了它自己以外的其他[源](https://developer.mozilla.org/zh-CN/docs/Glossary/Origin)（域、协议或端口），使得浏览器允许这些源访问加载自己的资源。

简单来讲，就是如果 `A.com` 的网站想要访问 `B.com` 网站上的资源，需要 `B.com` 配置 CORS 来同意。在现在的情况下，`imageport.app` 相当于 `A.com`，而你的 S3 储存桶的链接类似于 `B.com`，因此我们需要在 S3 储存桶那边配置 CORS 策略来同意来自 `imageport.app` 的访问请求。

</Callout>

为了正常使用，你需要

1. 允许当前面板的完整 Origin，包括协议和端口。官方实例是 `https://imageport.app`；自托管请使用自己的地址，可在测试详情中查看。
2. 允许当前应用使用的 `GET`、`HEAD`、`PUT` 和 `DELETE` 方法，不要求 `POST`。
3. 允许实际请求使用的 header。`AllowedHeaders: ["*"]` 是一种示例，合法的显式 header 列表和 `x-amz-*` 等通配符也可以使用。

CORS 规则支持 Origin 通配符，但不替代 IAM 或存储桶访问策略。详情中的辅助检查仅指出确定的 Origin 和方法缺项，不完整验证请求头，也不证明上传权限正常。

如果感到迷惑，可以查看上方的 [平台逐步教程](#platform-step-by-step-guide) 中是否有你使用的平台的详细教程，或者自行查询平台文档。

## 开始使用 S3 Image Port

1. 如果你按上文所说的配置好了 S3 储存桶，那你现在应该已经有了需要填入 S3 设置的所有信息！填入后点击「测试」，应用会使用当前前缀执行一次最多返回 1 个 key 的列表请求，10 秒后超时中止，不写入测试文件或图库缓存。空列表也算成功。
   前往[S3 设置](/zh/settings/s3) 填写。
2. 其他设置暂时保持默认值即可。
3. 前往[图库](/zh/gallery)，点击「加载图片」按钮，即可开始使用。

### 查看测试详情

「列表读取成功」仅表示当前浏览器可以读取当前存储桶和前缀的列表，未测试上传、删除或公共 URL。列表被拒绝也不代表不能上传。失败原因显示在测试按钮附近，点击「查看详情」可查看安全的错误码、可读的 HTTP 状态和请求上下文，并复制详情。

只有点击详情中的「检查 CORS」才会调用 `GetBucketCors`，它需要独立的 `s3:GetBucketCORS` 权限。辅助检查失败不改变列表结果，无需为了测试而扩大凭证权限。只有服务明确返回 `NoSuchCORSConfiguration` 时，应用才会报告未配置 CORS。

若浏览器没有提供可读响应，应用无法区分 CORS、网络等具体原因，也无法取得被 CORS 隐藏的 HTTP 状态。可打开开发者工具，在 Console / Network 中查看本次请求，再重试。
